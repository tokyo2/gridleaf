Deploying

Put the site online for free on Cloudflare Pages, Netlify or GitHub Pages, or upload it to any web host.

Folio builds a static site: plain HTML, CSS and images in dist/. Any static host can serve it, and no server or database is needed.

Before you deploy

  1. Set site.url to your real address and site.demoMode to false.
  2. Replace the demo products, posts, testimonials and images.
  3. Run npm run build and fix anything it reports.
  4. Put the project in a Git repository (GitHub, GitLab or Bitbucket) for automatic deploys.

Every host needs the same three settings:

Setting Value
Build command npm run build
Output (publish) directory dist
Node.js version 22.23.4 or newer (the included .nvmrc pins 22.23.4)

Cloudflare Pages

  1. In the Cloudflare dashboard, open Workers & Pages, create an application and choose Pages, then connect your Git repository.
  2. Pick the Astro framework preset, or enter the build command and output directory above.
  3. If the build uses an older Node.js, add an environment variable NODE_VERSION with the value 22.23.4.
  4. Deploy. Every push to your main branch deploys again.

Without Git, choose Upload assets and drag in the dist folder after running npm run build.

Netlify

  1. In Netlify, choose Add new site → Import an existing project and pick your repository.
  2. Build command npm run build, publish directory dist. Netlify reads .nvmrc for the Node.js version.
  3. Deploy.

Without Git, drag the dist folder onto Netlify’s manual deploy page. For Netlify Forms, see Forms.

GitHub Pages

Check your plan first. On GitHub Free, Pages only works from a public repository, and your Folio licence doesn’t allow publishing Folio’s source code publicly. Use a private repository on a paid GitHub plan, or use Cloudflare Pages or Netlify, which deploy private repositories for free.

  1. In folio.config.ts, set url to https://USERNAME.github.io and base to '/REPOSITORY' (or leave base as '/' for a USERNAME.github.io repository or a custom domain).
  2. Create .github/workflows/deploy.yml:
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: withastro/action@v6
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v5
  1. In the repository, open Settings → Pages and set Source to GitHub Actions.
  2. Push to main. The site appears at https://USERNAME.github.io/REPOSITORY/.

Preview deploys with environment variables

SITE_URL and SITE_BASE, when set as environment variables during the build, override site.url and site.base without editing the config. For example, a GitHub Pages workflow can set them in the build job:

    env:
      SITE_URL: https://${{ github.repository_owner }}.github.io
      SITE_BASE: /${{ github.event.repository.name }}

Any other host

Run npm run build and upload the contents of dist/ to your host’s web folder (for example with SFTP).

Custom domain

Add the domain in your host’s dashboard and follow its DNS instructions, then set site.url to the new address and deploy again.
